# Buyer interpretation and category expectations

Used by [choose-frame](../.claude/skills/choose-frame/SKILL.md) to select a frame and write its expectation table, and by [design-category](../.claude/skills/design-category/SKILL.md) to decide whether a new category is warranted and how its boundaries and adoption work.

## A frame is a set of borrowed expectations

When a buyer hears "it's an X", they import what they know about X: who buys it, what it replaces, which features it must have, what it costs, how long adoption takes. Ries and Trout described positioning as the place an offer occupies in the prospect's mind relative to what is already there (*Positioning: The Battle for Your Mind*, 1981); Dunford treats the market frame as the context that makes the differentiated value obvious (see [alternatives and value mechanisms](alternatives-and-value-mechanisms.md)). Used here: a frame is chosen for the expectations it creates, and those expectations are a testable claim about the buyer, not a slogan.

| Expectation dimension | Question to ask of a frame | Typical mismatch |
| --- | --- | --- |
| Buyer | Who does the frame tell the buyer this is for? | Enterprise-sounding frame for a solo buyer |
| Purpose | Which job does the buyer assume it does? | Buyer assumes a broader job than the offer covers |
| Competitors | What will the buyer compare it with? | Comparison with a category leader on features the offer lacks |
| Features | Which features are assumed present (table stakes of the frame)? | A frame implying mobile capture when it is only planned |
| Price | Which price range does the frame anchor? | Frame anchors a subscription when the offer is a one-off licence, or the reverse |
| Adoption | How much setup and change does the buyer expect? | Frame implies plug-and-play when conversion work is needed |

## Three kinds of frame

| Frame | Development question | Comparison consequence |
| --- | --- | --- |
| Existing category | Which familiar expectations make the value easy to understand? | Test fit with table stakes and the alternatives buyers consider |
| Narrower frame | Which buyer situation makes a more specific advantage useful? | Assess clarity, scope and the parent frame's expectations |
| New category | What distinction in the owner's perspective could give buyers a useful way to compare? | Develop plausible members, a demonstration and a workable adoption path |

Develop each kind far enough to compare its contribution to the venture. Choose the frame that best serves the buyer and owner ambition; retain a valuable category option for further development.

## Education burden

The education burden is the understanding a buyer must acquire before the leading value is obvious. Estimate it qualitatively: how many new ideas the buyer must accept, whether demonstration in one session shows the value, and whether the buying route allows that session. A frame with a heavy burden suits a route with long, guided contact; a self-serve route needs a frame whose value is visible on first contact.

## Criteria for a strong category

Develop a category through three connected questions:

1. **Real distinction.** What difference in problem, approach or outcome becomes visible, and what can a buyer understand or do with it? Start from the owner's perspective and work through a concrete use.
2. **Plausible members.** Who could belong besides the venture? Test membership on tools, services and neighbouring approaches; sharpen the boundary until it supports a meaningful comparison.
3. **Adoption path.** Which audience can apply the distinction first, what demonstration makes it inspectable, and how could language and practice spread? Connect this path to the commercial route and ambition.

Use these criteria to develop and compare options with existing and narrower frames. A weak distinction prompts better construction; a comparison may select another frame while keeping a worthwhile category as a live option.

## Boundary tests

Test membership on representative cases before naming:

- At least one plausible member that is not the venture's offering.
- At least one plausible neighbour excluded for a stated distinction.
- A case near the boundary decided by the condition, not by preference.

If the only member is the venture's own product, the category is a product description; return to choose-frame.

## Design and test buyer interpretation

State what a buyer should understand, compare and expect from the frame. Build a description or demonstration and test the interpretation through an unaided explanation, a comparison task or application to a fresh case. Use the response to improve the frame and its expression.

Put the expected interpretation and testing action in its basis record. Observed comprehension cites the actual response; owner acceptance establishes the chosen direction. Meaning can develop the intended interpretation while its empirical test remains an identified next action.

## Failure modes

| Failure | Signal | Correction |
| --- | --- | --- |
| False expectations | A consequential expectation exceeds the offering | Resolve the mismatch or revise the frame |
| Feature-list category | Membership describes only the venture's product | Develop the approach or outcome distinction and test plausible members |
| Adoption path underdeveloped | A name exists without a demonstration or route to use | Build the demonstration and identify the first audience and reuse task |
| Existing frame defended by default | Comparison contains no developed category option | Develop the owner's perspective into a category and compare all three frame kinds |
| Scope drift | The frame changes the venture's intended audience | Keep a scoped focus or prepare a venture-definition choice |
| Interpretation asserted as observed | Buyer understanding has no response record | State the intended reading in its basis and execute or prepare the test |

## Worked application

Illustrative fixture: fictional venture.

Brindlewick develops own-format reporting from the conviction that professional judgment should shape a report. The category includes tools and services that carry captured findings into an inspector-controlled structure; fixed vendor layouts and fully manual templates supply useful boundary contrasts. A converted report gives inspectors a concrete demonstration and an application they can teach.

Compare this option with inspection report software and report software in your own format. The narrower frame offers a short explanation for the first purchase; the category opens a wider professional idea. Choose the narrower commercial frame and develop the category as a live option. Test whether inspectors can explain the distinction and apply it to a fresh report comparison; keep planned phone photo sync explicit in the expectations table.
